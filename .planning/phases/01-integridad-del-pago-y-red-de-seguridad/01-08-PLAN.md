<objective>
Cerrar INFRA-01 e INFRA-02: un cron mantiene despierto el proyecto de Supabase tocando la
base de verdad, y si la base no responde llega una alerta antes de que un cliente se
encuentre el 500.

El proyecto de Supabase esta en plan free y se autopausa por inactividad. Ya paso una vez
en produccion y tiro abajo el libro de reclamaciones con un HTTP 500 — una funcionalidad
legalmente obligatoria bajo la Ley N° 32495, con multa de aproximadamente 1 UIT. Ahora el
mismo riesgo amenaza tambien el camino de cobro.

El cron hace dos cosas en la misma pasada (D-16, porque Vercel Hobby permite una sola
ejecucion diaria):
  1. **Keep-warm real:** una query contra `pedidos`. D-14 es explicito: Supabase mide
     inactividad por queries que llegan al proyecto, no por visitas al dashboard ni por
     pings a una ruta de Next que devuelve 200 sin tocar la base. Un cron que pinguea una
     ruta vacia "siempre funciona" en los logs de Vercel mientras el proyecto se pausa igual.
  2. **Reconciliacion:** lista cargos recientes en Culqi y busca los que no tienen fila en
     `pedidos`. Si encuentra huerfanos, alerta. **No crea el pedido** (D-12) — detecta y
     avisa, la decision queda en manos de un humano.

Esto sustituye a cualquier razonamiento sobre los reintentos de Culqi (D-10): en vez de
adivinar cuando el webhook fallo, se compara el estado real de los dos lados una vez al dia.

Output: `vercel.json`, la ruta de cron y su suite de tests.

**Punto de despliegue seguro:** todo es aditivo. Una ruta nueva y un archivo de config nuevo.
No toca `app/api/charge/route.ts` ni el webhook. Riesgo de despliegue: cero.
</objective>

De RESEARCH.md §Pattern 3 (verificado contra vercel.com/docs el 2026-08-25):
- Vercel manda automaticamente el valor de la env var `CRON_SECRET` como header
  `Authorization: Bearer <valor>` en cada invocacion de cron. El handler solo compara.
- `vercel.json` con `{ "$schema": "https://openapi.vercel.sh/vercel.json", "crons": [
  { "path": "/api/cron/reconciliacion", "schedule": "0 9 * * *" } ] }`
- **Vercel Cron corre SIEMPRE en UTC**, sin excepcion. `0 9 * * *` = 09:00 UTC = 04:00 Lima
  (UTC-5, sin horario de verano). Horario de bajo trafico, elegido a proposito.
- En Hobby la ejecucion puede caer en cualquier minuto dentro de esa hora, nunca al minuto
  exacto, y la entrega es best-effort: puede duplicarse o saltarse, sin reintento automatico.
  El diseno tiene que tolerar las tres cosas.

De `lib/supabase.ts`:
- `getSupabaseAdmin()` tira `Error("Faltan SUPABASE_URL o SUPABASE_SERVICE_ROLE_KEY")` si
  faltan las env vars. El cron tiene que distinguir ese fallo de configuracion del fallo
  de "la base esta pausada" — son problemas distintos y el mensaje de alerta debe decir cual es.

De `lib/culqi-verificar.ts` (plan 01-07):
- `consultarCargo(id)` sirve para verificar UN cargo. Para listar cargos recientes hace falta
  `GET https://api.culqi.com/v2/charges` con parametros de fecha. La forma exacta de la
  paginacion y de los filtros de fecha NO esta verificada — `apidocs.culqi.com` es un SPA que
  no se pudo inspeccionar. La Task 2 tiene que resolverlo contra la API real, no asumirlo.

De `lib/alertas.ts` (plan 01-03):
- `alertaTelegram(mensaje: string): Promise<void>`, best-effort. Si faltan
  `TELEGRAM_ALERT_BOT_TOKEN`/`TELEGRAM_ALERT_CHAT_ID` cae a `console.error` sin romper nada.

De `proxy.ts:36-38`: el matcher cubre `/admin/:path*` y `/api/admin/:path*`. La ruta de cron
queda fuera, igual que el webhook — Vercel no puede autenticarse con Basic Auth.

De PITFALLS.md pitfall 13: el modo de fallo clasico es un cron que pinguea una ruta que
devuelve 200 sin tocar la base. Los logs de Vercel muestran exito todos los dias mientras el
proyecto de Supabase se pausa. El criterio de aceptacion tiene que verificar que la query real ocurre.

De `.env.example`: hay que documentar `CRON_SECRET` siguiendo el estilo del archivo
(comentario en espanol explicando para que sirve y que pasa si falta).

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| internet -> `GET /api/cron/reconciliacion` | Ruta publica en el dominio: cualquiera que adivine el path puede invocarla si no esta protegida |
